# EXIF Editor

一个基于 Java 和 Apache Commons Imaging 的 JPEG 图片 EXIF 批量处理工具。项目通过统一菜单提供三种处理方式：按参考时间偏移量校正拍摄时间、将文件最后修改时间写入 EXIF，以及在两个目录的同名图片之间复制完整 EXIF。

> 工具会在 `modify` 模式下替换原始图片。首次使用时请先备份照片，并使用预览模式核对结果。

## 1. 项目用途

本项目适合处理相机时间设置不正确、照片时间需要整体平移、根据文件时间重建 EXIF 拍摄时间，以及为处理后的图片恢复原图 EXIF 信息等场景。

项目只有一个入口类 `ExifEditor`，启动后通过菜单选择功能：

| 选项 | 用途 | 处理方式 |
| --- | --- | --- |
| `1` | 按参考时间批量校正照片时间 | `新时间 = 新参考时间 B +（照片原 EXIF 时间 - 原参考时间 T）` |
| `2` | 使用文件时间重写照片时间 | 将文件最后修改时间写入 `DateTimeOriginal` |
| `3` | 在同名图片之间复制完整 EXIF | 将 A 目录图片的全部 EXIF 覆盖到 B 目录的同名图片 |

程序通过无损方式更新 JPEG 的 EXIF 元数据，不主动重新编码图片内容。当前实现只扫描指定目录的第一层，不递归处理子目录。

## 2. 项目结构

```text
exif_editor/
├── pom.xml
├── README.md
└── src/
    └── main/
        └── java/
            └── ExifEditor.java
```

- `pom.xml`：Maven 构建配置，声明 Java 20 和 Apache Commons Imaging 依赖。
- `ExifEditor.java`：程序唯一入口，包含菜单和三种 EXIF 批处理功能。
- `target/`：执行 Maven 构建后生成的编译产物目录，不属于源代码。

## 3. 简单使用手册

### 3.1 环境要求

- JDK 20
- Maven 3.x
- 包含 EXIF 信息的 JPEG 图片

确认环境：

```powershell
java -version
mvn -version
```

### 3.2 选择功能和目录

运行程序后输入菜单编号：

```text
请选择操作：
1. 按参考时间差批量校正 EXIF 拍摄时间
2. 将文件最后修改时间写入 EXIF 拍摄时间
3. 将 A 目录下同名文件的完整 EXIF 写入 B 目录文件
0. 退出
```

选项 1、2 会提示输入待处理图片目录，直接回车可使用程序内保留的默认目录。选项 3 会分别要求输入来源目录 A 和写入目录 B。程序只处理目录第一层的 `.jpg`、`.jpeg` 文件。

### 3.3 编译项目

在项目根目录执行：

```powershell
mvn compile
```

也可以直接使用 IntelliJ IDEA 打开项目，等待 Maven 完成依赖加载后运行对应类的 `main` 方法。

### 3.4 方式一：按时间差批量校正

运行 `ExifEditor.main()` 并选择 `1` 后，程序依次要求输入：

1. 待处理图片目录。
2. 新参考时间 `B`，格式为 `yyyy-MM-dd HH:mm:ss`。
3. 原参考时间 `T`，格式为 `yyyy-MM-dd HH:mm:ss`。
4. 操作类型。

例如，原参考照片的正确基准应从 `2024-06-01 10:00:00` 调整到 `2024-06-01 10:05:00`，可输入：

```text
2024-06-01 10:05:00
2024-06-01 10:00:00
preview
```

程序会保持每张照片相对于原参考时间 `T` 的时间间隔，并把整组照片平移到新参考时间 `B`。操作类型输入除 `modify` 以外的任意内容时，只打印拟写入的时间，不修改文件。

确认预览结果正确后再次运行，并在操作类型中输入：

```text
modify
```

### 3.5 方式二：使用文件最后修改时间

运行 `ExifEditor.main()` 并选择 `2`，输入图片目录后，再输入除 `modify` 以外的任意内容，可预览每张图片拟写入的时间：

```text
preview
```

确认无误后再次运行并输入：

```text
modify
```

程序会读取每个文件的最后修改时间，并写入 EXIF 的 `DateTimeOriginal` 字段。

### 3.6 方式三：复制同名图片的完整 EXIF

选择 `3` 后依次输入：

1. EXIF 来源目录 A，例如 `D:\Pictures\ORG`。
2. EXIF 写入目录 B，例如 `D:\Pictures\DST`。
3. 操作类型。

程序按完整文件名匹配两个目录中的 JPEG。例如：

```text
ORG/1.JPG  -> DST/1.JPG
ORG/2.jpg  -> DST/2.jpg
```

预览时输入 `preview`，程序只列出匹配关系；确认后再次运行并输入 `modify`，A 目录图片的完整 EXIF 将覆盖 B 目录同名图片原有的 EXIF。B 目录中没有同名文件，或 A 目录来源图片没有 EXIF 时会跳过，不会新建图片。

> “完整 EXIF”包括 EXIF 中的相机信息、拍摄时间、GPS 等目录和字段，不包括 XMP、ICC 配置文件等非 EXIF 元数据。

### 3.7 命令行运行（可选）

除 IDE 外，也可以通过 Maven Exec 插件运行入口类：

```powershell
# 启动统一菜单
mvn org.codehaus.mojo:exec-maven-plugin:3.5.0:java "-Dexec.mainClass=ExifEditor"
```

首次执行时 Maven 可能需要联网下载插件和依赖。

## 使用注意事项

- 实际修改前务必备份原始图片，并先使用预览模式检查时间。
- 只有操作类型精确输入 `modify`（不区分大小写）时才会修改图片。
- 当前实现主要面向带有 EXIF 元数据的 JPEG；其他格式、无 EXIF 图片或损坏文件可能被跳过或输出异常信息。
- 程序只处理配置目录的第一层内容，不会递归扫描子目录。
- 修改过程会在目标图片所在目录创建临时文件，写入成功后再替换原文件；请确保目录可写且磁盘空间充足。
- 选项 3 只修改 B 目录中的图片，A 目录只读；B 目录原有 EXIF 会被来源图片的 EXIF 整体覆盖。
- 时间使用运行电脑的本地时区；选项 2 的结果会受到文件最后修改时间准确性的影响。
